## Critical findings

1. **Watchdog silently dead since Oct 12** — Scheduled Task `M365Sphere-Watchdog`
   was registered with the default `ExecutionTimeLimit` of 72 h; Task Scheduler
   killed the script three days after the Oct 9 logon, so the two server deaths
   on Oct 16 had no watchdog. **FIXED**: `scripts/watchdog.ps1` rewritten
   (stdout/stderr redirection to `data/server-out.log`/`server-err.log`, API
   healthcheck with 3-strike restart), `scripts/register-watchdog.ps1` created
   (ExecutionTimeLimit 0, battery-proof flags), task re-registered live.
2. **Crash evidence systematically lost** — V8 fatal errors (likely OOM during
   live→live MIME streaming; the probable cause of both deaths) went to an
   unredirected stderr. **FIXED**: watchdog redirection + `process.on('exit')`
   marker in server.js.

## High findings

3. **Updater zip without integrity check** (repo compromise → RCE with tenant
   creds on disk). **FIXED**: mandatory `<zip>.sha256` sidecar asset verified
   before apply; build-installer.ps1 emits it. NOTE: releases without the
   sidecar now fail update checks by design.
4. **`robocopy /MIR` destructive mirror** wiped anything not in the zip and not
   excluded (docs/, .agents/). **FIXED**: allow-list mirror; server always
   relaunched even on failure; npm-install failure aborts the swap.
5. **hiddenCount blind spot** — engine full-re-list self-heal permanently
   misclassified listing-invisible (bulk PST-imported) items as "hidden",
   letting folders/mailboxes report done over missing mail. **FIXED**:
   `hiddenCountAt` timestamp, 30-day TTL revalidation, warning on fresh gaps.
6. **Move-email within-batch verified-skip collision** — items uploaded earlier
   in the same run poisoned the destination key set; later same-subject+
   receivedAt items were retired to Deleted Items WITHOUT a destination copy
   (observed live: ~180 items across the pc-2 migration, all recovered via
   `scripts/move-pc2-verify-skips.js`). **FIXED** in `lib/moveemail.js`
   (both flows) and `lib/copyemail.js`: batch-local keys no longer count as
   verified (Message-ID adds kept — strong identity).
7. **Interrupted jobs invisible** after a crash. **FIXED**: startup warn lines
   + dismissible TasksPanel banner (24 h window).

## Medium findings (all FIXED)

- `allowRemote` escape hatch → loud warning + header-only token when on.
- Live→live move to mailbox root flattened source structure → new `fullPath`
  option (engine + `/api/move-email` + MoveEmailPage checkbox, default on for
  root placements); retries preserve it.
- `safeName` Windows reserved names / trailing dots; `preview.js` scope
  whitelist (defense-in-depth).
- pstingest random MIME boundary broke sha256 idempotency → deterministic
  boundary (first re-ingest of pre-fix PSTs rewrites those files once).
- EXO export `sent`-only KQL missed no-sent-date items → catch-all `nosent`
  chunk per mailbox (`received>=1970-01-01 AND NOT sent>=1970-01-01`).
- move_email_plan crash window (199 rows) → 5 s time-based flush.
- Dedupe local fuzzy apply moved without content verification → fingerprint
  verify before move (matches the live path's discipline).
- `/api/stop/sizes` didn't kill the EXO PowerShell child; EXO PST download not
  abortable mid-file → both fixed (aborter threaded into `_downloadFile`).
- Disk preflight only on `/api/backup` → shared `diskCheck()` helper, now also
  on `/api/pst` and per EXO chunk.
- `items(upn, sha256)` index added (per-group full scans over 469k rows).
- StorageManager + PstPlanBuilder showed the synthetic "Archive root" node →
  canonical flatten applied; TasksPanel raw UTC slice → `fmtTime`.
- Installer `APPVER` hardcoded 1.0.0 → `/DAPPVER` from package.json; Node < 22
  warning → hard stop (better-sqlite3 prebuilt requirement).

## Accepted / deferred

- **getMessageMime buffers whole MIME** (graph.js) — every caller needs the
  full buffer; streaming would require an invasive fetchItem tee. Accepted.
- **50-item random-sample verify** (engine.js) — documented limitation.
- **Watchdog API-healthcheck variant lost Oct 2** — restored in the rewrite.
- Server deaths' exact cause unprovable retroactively; the new redirection
  captures the next one.
- The move-email engine's fuzzy-only skips proved 100% protective this week
  (every fuzzy skip was unique content) — semantics kept.
